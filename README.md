Разработайте совместно с ИИ сервис для бронирования календаря

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers

## Демо

Приложение задеплоено: https://call-scheduler-hexlet.onrender.com

Бесплатный инстанс Render засыпает без трафика, поэтому первый запрос после паузы может занять до минуты.

## Стек

- **Backend:** Python 3.13, FastAPI, SQLAlchemy 2 (async), SQLite, Alembic
- **Frontend:** React 19, TypeScript, Vite, Tailwind CSS v4, shadcn/ui
- **Контракт:** TypeSpec → OpenAPI → TypeScript- и Pydantic-модели
- **Инструменты:** mise, uv, Docker, Playwright

## Использование

```bash
mise run dev
```

Бэкенд поднимется на `http://localhost:8000`, фронтенд — на `http://localhost:5173`.

### Docker

Образ собирается из `Dockerfile` в корне репозитория. Внутри фронтенд собирается Vite, а FastAPI отдаёт и статику, и API с одного origin.

```bash
docker build -t call-scheduler .
docker run --rm -p 8000:8000 -e PORT=8000 call-scheduler
```

Приложение откроется на `http://localhost:8000`. Порт задаётся переменной окружения `PORT`, миграции Alembic применяются при старте контейнера.

### Деплой на Render

- Приложение: [https://call-scheduler-hexlet.onrender.com](https://call-scheduler-hexlet.onrender.com)
- Панель сервиса: [dashboard.render.com/web/srv-dbriiih5efls73anlt7g](https://dashboard.render.com/web/srv-dbriiih5efls73anlt7g)

Конфигурация сервиса — в `render.yaml`: Render собирает образ из этого же `Dockerfile`, передаёт контейнеру `PORT` и проверяет `/health`. Каждый push в `main` запускает новый деплой.

#### Подключение MCP-сервера Render

MCP-сервер уже прописан в `opencode.json`. Секретов в репозитории нет: используется OAuth, токен хранится в OpenCode вне проекта.

1. Откройте проект в OpenCode.
2. Выполните `/mcps` и выберите `render`.
3. Нажмите «Connect» и войдите в аккаунт Render в браузере.
4. Убедитесь, что сервер подключён: `opencode mcp list` → `render connected`.
5. При необходимости выберите workspace: «Set my Render workspace to …».

API-ключи и другие секреты в `opencode.json` не добавляются. Для неинтерактивных окружений Render поддерживает ключ через `{env:RENDER_API_KEY}`, но в этом проекте он не используется.

#### Ограничение хранения данных

Данные лежат в SQLite-файле `app.db` внутри контейнера. У бесплатного веб-сервиса Render файловая система эфемерная: при передеплое, перезапуске или переносе инстанса база теряется. Постоянного диска на free-плане нет.

- локально `backend/app.db` сохраняется между запусками;
- на Render данные живут до ближайшего редеплоя и подходят только для демонстрации;
- для постоянного хранения нужен Render Disk (платный план) или внешняя БД, например PostgreSQL.

## Как пользоваться

При переходе на сайт сервиса "Календарь звонков" вас встречает окно с приветствием. Здесь вы можете ознакомиться с возможностями сервиса и перейти к списку типов встреч.

### Если вы гость

На следующей странице вы можете просмотреть список типов встреч и выбрать подходящий.
Перейдя к конкретному типу встречи, вы можете записаться на звонок. Для этого выберите удобные дату и время из предлагаемых вариантов.
После выбора даты и времени, заполните сведения о себе и нажмите кнопку "Подтвердить запись".
Дождитесь подтверждения бронирования. При необходимости вы можете продолжить бронирование.
Для просмотра бронирований откройте "Предстоящие события" по ссылке в верхнем правом углу страницы.

### Если вы владелец

На странице типов встреч вы можете добавить новый тип встречи, определить даты и доступные слоты времени для звонков.
После добавления типа встречи, в разделе "Предстоящие события" вы можете просмотреть список запланированных броней и просмотреть сведения о записях на звонки.
