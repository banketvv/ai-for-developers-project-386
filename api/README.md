# Контракт API

Здесь живёт **единственный источник правды** для HTTP API «Календаря звонков».
Маршруты и модели описаны на [TypeSpec](https://typespec.io) — языке описания API,
из которого собираются артефакты для обеих сторон.

## Зачем это нужно

Раньше сервер, клиент и документация договаривались «на словах»: тип ответа
писали три раза — в Pydantic, в TypeScript и в голове. Теперь форма данных
описана один раз, а всё остальное **генерируется**:

```text
api/*.tsp                 описание маршрутов и моделей (руками)
      │
      ├─ tsp compile ──▶ api/openapi/openapi.yaml          OpenAPI 3.1
      │                        │
      │                        ├─ openapi-typescript ──▶ frontend/src/api/schema.d.ts
      │                        │                              (типы путей и схем)
      │                        └─ datamodel-codegen  ──▶ backend/app/schemas/contract.py
      │                                                       (Pydantic-модели)
      │
      └─ проверка в тестах ──▶ backend/tests/test_contract.py
                                  (маршруты, коды ответов и схемы сервера
                                   совпадают с OpenAPI)
```

Таблица ниже показывает, кто за что отвечает:

| Файл | Кто пишет | Что внутри |
|---|---|---|
| `api/main.tsp` | человек | сервис, импорты, пространство имён |
| `api/models.tsp` | человек | модели запросов, ответов и ошибок |
| `api/*.tsp` (кроме `models.tsp`) | человек | маршруты по ресурсам |
| `api/openapi/openapi.yaml` | генератор | OpenAPI 3.1 |
| `frontend/src/api/schema.d.ts` | генератор | TypeScript-типы путей |
| `backend/app/schemas/contract.py` | генератор | Pydantic-модели |

Сгенерированные файлы **не редактируются руками**: следующая генерация их перезапишет.

## Команды

Из корня репозитория:

```bash
mise run api:generate   # пересобрать OpenAPI, TS-типы и Pydantic-модели
mise run api:check      # упасть, если сгенерированное разошлось с TypeSpec
```

`api:check` входит в `mise run check`, поэтому устаревший контракт валит CI.

## Как изменить API

1. Поправьте `.tsp`-файл (модель или маршрут).
2. Выполните `mise run api:generate`.
3. Проверьте, что `mise run check` зелёный; при необходимости поправьте
   сервер и клиент под новый контракт.
4. Закоммитьте и TypeSpec, и пересобранные артефакты — они лежат в git,
   чтобы сборка не зависела от сети и версий генераторов.

## Клиент на фронтенде

`frontend/src/lib/api.ts` создаёт типизированный клиент из `schema.d.ts`:

```ts
apiClient.GET('/api/v1/meeting-types') // путь и ответ проверяет компилятор
```

Модули `src/lib/meeting-types.ts`, `bookings.ts`, `slots.ts` и `session.tsx`
только оборачивают вызовы клиента и приводят ошибки к `ApiError`.

## Сервер на бэкенде

У FastAPI нет генератора, который бы делал «заготовки маршрутов», не выбрасывая
уже написанный сервер: `openapi-generator` и его аналоги собирают целый каркас
приложения. Поэтому маршруты и бизнес-правила написаны руками, а из контракта
берутся **модели** (`app/schemas/contract.py`). Совпадение маршрутов со
спецификацией проверяет `backend/tests/test_contract.py`:

- набор путей и методов;
- набор кодов ответов у каждой операции;
- поля и обязательность полей в запросах и успешных ответах.

Нормализация (`trim`, пустая строка → `null`, нижний регистр почты) и русские
тексты ошибок живут в тонких наследниках сгенерированных моделей —
`app/schemas/base.py` и модулях рядом.
