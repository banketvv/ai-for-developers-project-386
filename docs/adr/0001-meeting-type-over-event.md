# Тип встречи вместо события

Домен сервиса — «типы встреч», а не «события»: тип встречи это серия встреч с названием, описанием и длительностью, которую задаёт владелец. В README и в макетах слово «событие» встречается в двух разных смыслах сразу (и как тип встречи, и как бронь), поэтому доменный термин закреплён как «Тип встречи», а «Бронь» описывает факт записи гостя на слот. Переименование затрагивает API, БД и UI, поэтому фиксируем его до начала реализации.

## Considered Options

- **Оставить «Событие»** — привычнее по README, но в коде пришлось бы различать `Event` (тип встречи) и `Event` (бронь), что гарантирует путаницу.
- **«Тип события»** — так подписан экран выбора в макете, но слово «событие» в домене не значит ничего определённого.

## Consequences

- В коде, API и БД живут только «Тип встречи» (`MeetingType`), «Слот» (`Slot`), «Бронь» (`Booking`).
- Подпись «Предстоящие события» на экране — это UI-ярлык списка броней, а не доменный термин.
